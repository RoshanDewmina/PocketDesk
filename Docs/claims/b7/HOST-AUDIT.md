## C4 source evidence

The menu popover requires Keep Sharing / Stop Sharing inline confirmation while live (`RemoteHost/HostPopoverView.swift:211–219, 269–272`); Settings uses a confirmation dialog (`RemoteHost/HostSettingsView.swift:81–86`). `RemoteHost/RemoteHostApp.swift:152` binds the action to `model.stopSharing`.

`RemoteHost/HostModel.swift:1017–1025` cancels a timed pause, clears `wantsSharing`, persists `sharingEnabled=false`, and calls `stop()`. This prevents spontaneous resume, including relaunch preference restoration. The coordinator-reset reconciliation only finishes stopped state and cannot revive explicit sharing-off (`RemoteHost/HostModel.swift:3556–3577`). `stop()` at 1827–1842 ends guests, begins Big Text restoration, calls the curtain-lift policy (which preserves Away cover authority), invalidates text focus, stops browser sharing, releases held/queued remote input, marks sharing inactive, releases keep-awake, and stops the coordinator.

`RemoteShared/RemoteCoordinator.swift:900–908` marks the coordinator stopped, cancels retry/route expiry/renewal, closes signaling, and resets the session. `resetSession()` at 933–960 closes the media, discards queued motion/input context, clears session state, and synchronously invokes `onEnded`. The host callback (`RemoteHost/HostModel.swift:554–558`) calls `endCapture` (2407–2440), which disables input, resets clipboard/file transfer, stops lifecycle/load/telemetry, cancels pending capture, and calls `capture.stop()`.

`RemoteHost/RemoteCapture.swift:473–494` invalidates ownership and immediately fences/detaches the capture session; the returned asynchronous task performs stream shutdown (`1015–1036`). `RemoteShared/PeerMedia.swift:1459–1510` fences/closes channels, audio, frame ownership and the peer connection. This supports immediate authority/frame admission revocation, not a measured zero-delay physical disconnect or a measured immediate display-mode restore. Big Text restoration is separately asynchronous.

## C5 source evidence and limits

`RemoteShared/RemoteCoordinator.swift:1484–1549` schedules service-offered renewal without a total elapsed-session ceiling. `Server/src/server.ts:113–114, 194–197, 350–367` has a 30-minute renewable room lease; a valid renewal moves the deadline to a full lease from now. Approval is rechecked; expired/revoked rooms fail closed. Native background hold expiry (`RemotePhone/RemotePhoneApp.swift:2362–2393`) is lifecycle cleanup, not a free-session duration paywall.

The **authoritative shipped Workers backend is separate from the private Bun fixture service**. `Backend/src/config.ts:62–64, 82` defaults `ROOM_LEASE_SECONDS` to 1800 and derives `leaseMs`, requiring the lease to be shorter than TURN credential life. `Backend/src/room.ts:1056–1149` validates active socket/host/client ownership, a still-live lease, approval, and route deadline before renewal; paid route renewal rechecks verified entitlement and rejects stale socket/epoch/revision/ownership after awaited work. At `1087–1096`, successful renewal moves `lease_ends_at` to `now + leaseMs` and publishes a fresh route revision/deadline for a connected phone. An unentitled local route uses the renewed lease deadline; a paid route additionally remains bounded by the verified entitlement deadline. Alarms enforce route/lease expiry if renewal fails (`room.ts:361–364, 393–400`). There is no original-session-start total-duration ceiling in this renewal path. This is a source conclusion, not an observation of the deployed config or a live Worker renewal.

The native coordinator advertises both `renew.1` and `route.1` (`RemoteShared/RemoteCoordinator.swift:803–815`) and accepts a newer valid route policy, cancels the previous route-expiry task, and arms the new deadline (`972–994`); same-access renewal does not tear down media. Paid access expiry and fail-closed missed-renewal teardown remain deliberate. Existing backend fixtures in `Backend/test/renewal.test.ts` and `Backend/test/route.test.ts` are testable coverage of this separate service; they were not run by this host-only audit. The Bun/core integration tests below do **not** exercise this Workers route-authority renewal, so they cannot prove the shipped backend works through 35 minutes.

The native **owner-local offline transport** is another path, separate from cloud/Bun leases: `RemoteShared/RemoteCoordinator.swift:62, 322–344` admits only a fresh authenticated owner-local epoch and excludes cloud renewal/policy messages from that peer. Its transport timeout (`RemoteShared/LocalSignalingTransport.swift:105–112`) is an unauthenticated handshake deadline; successful authentication cancels it (`249–251`). No total session-duration ceiling was found in this local transport. This source review does not verify physical offline-LAN behavior or a 35-minute session.

`RemoteTests/SessionRenewalTests.swift:92–113` models 130 minutes; `153–176` advances a scripted scheduler and confirms lease/credential freshness past 30/60/120 minutes. These run no real 130-minute media stream. `253–268` checks stop cancels renewals and ignores late replies.

`RemoteTests/SessionRenewalIntegrationTests.swift:81–113` uses a real local Bun service and two real WebRTC peers across several 3-second leases for about 10 seconds, retaining media identities and checking control delivery. It does not push video frames during that renewal test. The 9-second refresh test (`180–215`) does push/generated-decoded video across refresh/ICE restarts, but forces the “Relay” policy label over an actual direct loopback transport and supplies fake TURN credentials; it does not verify TURN service, production/backend paid route, phone hardware, free physical LAN route proof, or 35 minutes. Its test coordinators explicitly enable legacy private route fixtures (`54–60`).
