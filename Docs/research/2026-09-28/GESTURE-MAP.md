# Phone gestures and Mac trackpad actions

Research checked 28 September 2026. This is a feasibility map, not a claim of current physical behavior. Apple's [Mac Multi-Touch list](https://support.apple.com/en-gb/102482) says gestures can be disabled or reassigned in Trackpad settings; its December 2025 revision says Mission Control, App Exposé and Spaces may use **three rather than four fingers** on some macOS versions. Match the *action*, not a fixed finger count. The [iOS/iPadOS release-note index](https://developer.apple.com/documentation/ios-ipados-release-notes/) and [macOS index](https://developer.apple.com/documentation/macos-release-notes) were checked for platform context; no new OS-specific gesture API is assumed here.

PocketDesk's inspected code already has a relative pointer, click/double-click, two-finger secondary click, phase-aware two-axis scroll, a deliberate double-tap-and-hold drag, and local viewport zoom/navigation in `NativeGestureEngine`. The host's authenticated `key` route supports Control, Command, Option and Shift plus arrows/letters; it does **not** currently map F3 or Fn. The continuation implements two-finger viewport pan/pinch and double-tap zoom in View mode, plus three-finger directional swipes in Control mode. Signed builds and the core gesture checks pass; **physical phone/Mac gesture verification remains pending**.

| Mac trackpad intent | Public action PocketDesk can offer | Status and limit |
| --- | --- | --- |
| One-finger pointer/tap; two-finger right-click; two-axis scroll; drag | Existing authenticated pointer, button, scroll and hold commands | Code present; physical feel and timing still need device testing. Mac three-finger drag is an optional Accessibility setting; PocketDesk's explicit hold is an alternative, not the same system gesture. [Apple gestures](https://support.apple.com/en-gb/102482) |
| Mission Control (swipe up) | Control–Up Arrow through existing key route | Implemented through three-finger recognition; physical behavior pending. Apple documents this keyboard equivalent; the Mac shortcut can be changed. [Mission Control](https://support.apple.com/en-nz/guide/mac-help/mchlb7beb9af/mac) |
| App Exposé/current app windows (swipe down) | Control–Down Arrow through existing key route | Implemented; physical behavior pending; user-customized shortcut may differ. [Mission Control](https://support.apple.com/en-nz/guide/mac-help/mchlb7beb9af/mac) |
| Switch Spaces/full-screen apps (swipe left/right) | Control–Left/Right Arrow through existing key route | Implemented; physical behavior pending. This changes the Mac Space; it is not local viewport panning. [Apple Spaces guidance](https://support.apple.com/kk-kz/guide/voiceover/mchlp2699/10/mac/26) |
| Show Desktop (thumb + three-finger spread) | Public keyboard shortcut Command–Mission Control/F3, or a user-configured keyboard shortcut/Hot Corner | **Not available from today's key map:** F3/Fn are absent. Could extend the allowlisted key route and test the actual host shortcut. Do not substitute Control–Down; that is App Exposé. [Apple window guide](https://support.apple.com/en-nz/guide/mac-help/mchlb7beb9af/mac) |
| Look Up/data detectors (three-finger tap/Force click) | Control–Command–D for the selected word, or Control-click then Look Up | Key chord is representable now, but the selected/hovered target and app determine result; this cannot promise the exact data-detector popover. Offer as an explicit Look Up command after cursor/selection testing. [Apple shortcuts](https://support.apple.com/en-my/102650), [Look Up](https://support.apple.com/en-kw/guide/mac-help/mchl3983326c/mac) |
| Page back/forward (two-finger horizontal swipe) | Horizontal scroll already passes through; app/browser Back/Forward shortcut can be a separate action | App-specific: horizontal scroll may move content instead of navigating. Test Safari and other target apps; do not globally convert every sideways scroll to history navigation. [Apple gestures](https://support.apple.com/en-gb/102482) |
| Smart zoom (two-finger double-tap), pinch to zoom in an app | Local PocketDesk zoom preserves readability; app keyboard zoom shortcuts can be offered where supported | Local viewport zoom does **not** change the Mac app's zoom. App pinch/magnification is not equivalent to Command–Plus/Minus and has no reliable cross-app mapping through the existing pointer/key/scroll route. [Apple gestures](https://support.apple.com/en-gb/102482) |
| Rotate an item with two fingers | Use that app's visible rotate control or documented shortcut | App-specific; no universal public systemwide rotate action through PocketDesk's current route. [Apple gestures](https://support.apple.com/en-gb/102482) |
| Notification Centre edge swipe; Apps/Launchpad multi-finger pinch | Visible Mac UI or configurable Mac keyboard shortcut | No stable equivalent in current allowlisted keys. Keep optional explicit commands separate from core trackpad gestures. [Apple gestures](https://support.apple.com/en-gb/102482) |
| Force click / pressure-sensitive actions | Context click, Quick Look via selecting a Finder item then Space, Return for Finder rename, or app-specific controls | **No pressure/Force Touch emulation** from an iPhone touch screen or public key/scroll route. Apple documents these alternatives, with app-dependent behavior. [Force Touch alternatives](https://support.apple.com/en-bh/102309) |

**Input ownership and acceptance.** Keep View gestures local and Control gestures remote; when the finger count changes, cancel the previous owner and release held input before starting another. Do not broaden the existing authenticated input gate or synthesize private trackpad/gesture events. Apple's iPhone guide assigns three-finger swipes to text undo/redo and three-finger pinches to cut/copy/paste, so test conflicts around text fields and the software keyboard; iPad also has system multitasking gestures. UIKit says screen-edge system gestures normally take precedence and recommends leaving them so where possible. Treat these as design constraints rather than assuming every three/four-finger touch reaches PocketDesk. [iPhone text gestures](https://support.apple.com/guide/iphone/select-edit-and-move-text-iph1a9cae52c/27/ios/27), [iPad trackpad gestures](https://support.apple.com/en-gb/guide/ipad/ipad66ce6358/26/ipados/26), [UIKit system-edge guidance](https://developer.apple.com/documentation/uikit/uiviewcontroller/preferredscreenedgesdeferringsystemgestures).

On an actual phone and Mac, accept each proposed action only after confirming the phone detects the gesture without stealing iOS controls, the Mac receives the intended authenticated command once, the action matches the Mac's current shortcut settings, and cancellation/rotation/backgrounding cannot leave a drag or scroll active. Test both portrait and landscape, keyboard open/closed, and VoiceOver or other accessibility settings where relevant. “All Mac trackpad gestures” is not a defensible claim: the deliverable is broad, deliberate access to common actions with honest limits for pressure and app-specific gestures.
