## Availability and authority are separate

| Mac state | Existing source / bounded required outcome |
| --- | --- |
| Awake, current user unlocked | Existing authenticated route/capture/input authority still required. Keep-awake choice affects idle system sleep only. |
| Display asleep, system awake | Existing HostSleepPolicy keeps sharing registered; authenticated connection may call public IOPMAssertionDeclareUserActivity. No guaranteed capture until fresh health/frame proof. |
| System asleep | Own process cannot service a wake request. Another powered LAN peer sends an owner-configured magic packet; hardware/settings/actual wake remain separate gates. |
| Lid closed | Idle assertion does not prevent lid sleep; external display/power/hardware conditions remain physical capability gate. Never promise clamshell from assertion success. |
| Screen locked | Sharing/control/privacy outputs stop. No stored password, injected unlock or lock weakening. Unlock remains user/platform boundary. |
| Switched user | Current user's sharing/control stop; another user cannot inherit owner grant. |
| Logout | Per-user app/LaunchAgent unavailable until login; no claimed login-window control. |
| Restart | Explicit login item resumes after the applicable user login/permissions/route proof, not during preboot. Deliberate Quit remains respected by watchdog. |
| FileVault preboot | User password protects volume keys; ordinary app is not a preboot agent. No remote FileVault unlock claim or recovery-key/password handling. |
