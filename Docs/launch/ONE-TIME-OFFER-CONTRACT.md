Both requested offers are full unmetered Anywhere benefits purchased once. No hour cap or relay quota replaces that intent. Both sales paths are disabled. No production SKU, price, currency, founder cohort, price approval or relay economics approval is supplied. The existing subscription offering remains separate.

Native OneTimeOfferPolicy is a build-owned exact catalog. Recognition of an already approved product is independent of saleEnabled: disabling future sales does not revoke a verified purchaser's existing benefit. Purchase requires a recognized non-consumable, matching approved StoreKit localized price/currency, explicit price and long-term relay economics approvals, and a founder cohort approval for founder lifetime. Both kinds default to nil product IDs and all approvals unset. No Info.plist preference, pairing code, user text or transaction alone creates a catalog entry. Paywall cards appear only for products that pass every gate; localized one-time wording says no renewal, current service verification/pairing required, refunds/revocations remove that benefit, and an existing subscription is not cancelled automatically.

StoreKit reads verified current non-consumables for exact catalog products and own PURCHASED ownership, retaining revoked latest transactions solely as UI evidence. Typed kind is subscription/lifetime/founder. One-time economic periodEnd is nil; no fake far-future expiry. The strongest surviving one-time benefit or subscription supplies its own signed transaction. A refunded lifetime benefit does not erase a surviving founder benefit or active subscription. Duplicate purchase versions are ordered by signed purchase date; revocation wins a tie. Restore recovers billing only, never Mac trust/control/route identity; there is no IAP-to-web entitlement migration or automatic subscription cancellation. Old native subscription statuses and old DB rows remain subscriptions.

Backend configuration recognizes only exact deployment-owned LIFETIME_PRODUCT_ID/FOUNDER_PRODUCT_ID values; both absent by default. Catalog collisions, duplicate IDs and malformed IDs fail configuration. A verified Apple JWS must match bundle, accepted environment, allowed product, Non-Consumable type, absence of subscription expiry and own PURCHASED ownership. Unknown products remain rejected. Production/Sandbox one-time verification additionally calls the public Get Transaction Info endpoint with configured server credentials, verifies the returned JWS and exact original/current transaction/product/environment/app identity, and uses its current revocation state. Missing configuration, failed response, mismatched identity or storage trouble issues no authorization. Test Xcode handling remains restricted to dev/test; it is never enabled by this package on public deployments.
