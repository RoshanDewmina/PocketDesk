# Useful-session onboarding and acceptance

Source preparation now separates admitted fresh picture/Couch readiness, host-confirmed applied semantic input, and the person’s explicit read/navigate/edit/save outcome. These are different facts. Pairing QR, a connected socket, restoring a purchase, practicing gestures, motion acknowledgement and outbound click enqueue are not task completion. View-only reading can be confirmed without input; other outcomes require an actual applied-input fact, and still depend on the person’s statement that the task finished. A click receipt cannot prove a save or an edit.

The phone’s readiness uses the exact cached selected host record and authenticated current invitation, rotating presentation session/content/geometry identity, current route deadline, health age ≤ 2 seconds and active unconcealed scene. Picture additionally requires a fresh admitted frame/current track. Couch additionally requires its host capability, proven local route and current control readiness. Invalidation clears pending input evidence; track/content/geometry/session changes retire correlation. A bounded 32-request tracker uses exact requestID/kind/epoch/presentationSession/context and expires after 4 seconds. Modern hosts report actual posting results; older hosts can contribute only a matching successful textResult with preserved current context. No legacy click inference is made.

Session check is reachable on Home and the live session. It shows the three facts, asks the person to confirm one task, offers the local gesture coach again, a fixed-choice blocker questionnaire and explicit safe support-summary copy. There is no contact or automatic export. The summary excludes credentials, Mac identity and remote text/content. Coach practice never sends input to the Mac and never becomes task evidence. Automatic coach waits for genuine readiness rather than scanned QR.

Optional local funnel counters are off by default. Explicit consent saves bounded aggregate counts only, with no host/grant IDs, app names or remote payloads. Withdrawal deletes saved counters. Return after explicit End and session re-establishment after interruption are separate counters from completed outcomes; their classification is within this process only and is not cross-launch identity tracking. Question answers are fixed choices and in memory; counters, when allowed, record counts rather than content. No analytics endpoint is added.

New controls have 44 pt minimum targets, system Dynamic Type/Form scrolling, VoiceOver labels/values and no required animation. Existing session Reduce Motion behavior is preserved. Physical VoiceOver, Switch Control, largest accessibility sizes, landscape/keyboard obstruction, reachability of overlay and actual unfamiliar-user success remain acceptance gates.

Retained launch funnel: installation→first authorized fresh usable picture within 2 minutes remains a physical unfamiliar-user target. Record first useful applied input and user-confirmed task outcome separately, then a later return/reconnect. Do not relabel connection within 10 minutes as useful activation. Source fixtures do not establish the 2 minute target or real task success.

Existing Watch/alert source is prepared separately: minimized generic payloads, explicit notification authorization/test alert, stale activity deadlines and canonical Mac routing; Watch mirroring is iOS notification behavior, not a newly built Watch app. Live Activity/widget glance is status only, not background control or stale PiP authority. Provider/APNs, Apple Watch mirroring, lock-screen privacy, notification-tap exact pairing and real delivery remain physical/provider gates. No new background execution/audio/VoIP keepalive, provider configuration or installation occurred in this lane.
