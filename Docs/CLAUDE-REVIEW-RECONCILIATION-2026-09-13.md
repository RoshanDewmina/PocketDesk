## Second-pass conditions and their integration

1. **Specify the synthetic fixture.** PRODUCT 9B2 now names monospace code/stack traces, punctuation, indentation, syntax colors, selections, light/dark backgrounds, target resolution/scaling, recorded bitrate/crop factors, and a changing counter. It labels synthetic readability provisional until the real capture path is tested.
2. **Separate health and age thresholds.** PRODUCT 8 distinguishes the native 0.8-second capture-health cutoff from the provisional 600 ms displayed-frame input gate. Neither an advancing heartbeat nor RTT alone is accepted as proof of displayed-frame age.
3. **Name the capture entitlement decision.** The prototype has no dependency on Persistent Content Capture and no approval is claimed. Apple says permission must be requested for this entitlement. The review's broader assertion that every unattended or locked-host claim depends on it is not established by that documentation; actual OS behavior and any required approval must be checked for the specific later claim.
4. **Define T2 acceptance.** PRODUCT 9B2 now specifies advancing authorized embedded video, local fit/zoom/pan, enforced view-only scope, lifecycle behavior and a working T1 control fallback. The review's suggestion that remote touch-pointer input should be a T2 requirement was not adopted: that would contradict the view-only tier. Remote input belongs in T3.

No additional full review loop was necessary after these concrete additions. The second-pass verdict was conditional readiness, not a claim of zero risk; this record states exactly how the conditions were resolved.

## Decisive checks and limitations

- Parent reread the late user messages in the original conversation. Browser-first was explicitly accepted at 07:18:21 UTC. PRODUCT contains an eleven-row source mapping; the review's informal item count is not the authority for coverage.
- Parent checked `RemoteHost/RemoteCapture.swift`, including `CaptureHealthState`, and the native Origin rejection and binary control-channel behavior. Existing code is not proof of phone operation.
- [WebKit's policy](https://webkit.org/tracking-prevention/) documents storage partitioning, script-storage expiry and a Home Screen first-party exception. Browser enrollment must tolerate storage loss; no universal seven-calendar-day countdown is specified.
- [Apple TN2150](https://developer.apple.com/library/archive/technotes/tn2150/_index.html) is archived documentation about keyboard interception. It supports correcting the review's inference, not a current guarantee of successful secure-field injection. [Current event posting](https://developer.apple.com/documentation/coregraphics/cgevent/post%28tap%3A%29) likewise does not prove every protected UI accepts input.
- [Persistent Content Capture](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.persistent-content-capture) requires Apple's permission before use. No application was submitted and no entitlement was added.
- [WebRTC codec requirements](https://www.rfc-editor.org/info/rfc7742/) support inspecting actual negotiation. No codec/profile, permission-retention, latency, embedding or password-field experiment was performed in this planning task.

**Result:** feature coverage, competitor research, proposed implementation sequence, independent Opus 5 critique and parent reconciliation are complete. Implementation remains paused pending authorization. Physical phone/cellular/TURN and per-host embedding tests remain future gates.
