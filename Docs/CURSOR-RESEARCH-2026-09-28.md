# PocketDesk cursor-visibility research

Repo context confirmed: `RemoteHost/RemoteCapture.swift` already sets `configuration.showsCursor = true` (SCStreamConfiguration), so the Mac's real cursor is baked into the captured frame today. `RemotePhone/PointerLocator.swift` + `RemoteShared/PointerLocation.swift` implement a separate, on-demand "locator ring" protocol (probe/response over the data channel, 0.25s lifetime, only while actively moving) drawn as a stroked `Circle` overlay — this is the "ugly ring" the user wants to replace or drop.

## 1. Enlarging the system cursor programmatically

- **Setting**: `~/Library/Preferences/com.apple.universalaccess.plist` → `mouseDriverCursorSize` (float, 1.0 = normal, up to 4.0 in System Settings → Accessibility → Display → Pointer size). Also `cursorSharpness`/outline & fill color keys exist under the same domain for the outline/fill-color pickers.
- **No public API.** Apple ships no documented framework call to read/write this. It's a defaults-domain preference plus a private daemon (`universalAccessAuthWarn`/Accessibility subsystem) that reacts to it.
- **`defaults write` does not reliably apply live.** Multiple independent reports (Apple Community threads, MacRumors) confirm: writing the plist key updates the *stored* value (visible via `defaults read`) but the on-screen cursor only changes size when the change is driven through System Settings' own UI, which pushes a live update via the Accessibility private mechanism (likely a distributed notification / XPC call the System Settings pane makes, not merely a preference change). Simply broadcasting a generic `DistributedNotificationCenter` post is not documented to work either — no confirmed working recipe.
- **Permissions/TCC/SIP**: writing the defaults key itself needs no special entitlement, but it has no effect without the private trigger, and there is **no supported way for a third-party app to invoke that trigger** (confirmed by Apple devforums: "no supported way to programmatically add your app to accessibility... TCC requires user consent" — same pattern applies to driving system Accessibility display settings from outside System Settings).
- **Private APIs**: `CGSSetCursorScale` (SkyLight/CoreGraphics private, undocumented, reverse-engineered) is the mechanism System Settings itself likely uses under the hood. It is unstable across releases — "private APIs break on every major macOS release" (Cua/SkyLight writeup) — and unsupported/unversioned. No official Apple doc exists.
- **App Store implications**: calling private CGS/SkyLight symbols is a hard rejection risk under App Review Guideline 2.5.1 (no private API use). Since PocketDesk may go to the Mac App Store later, building a load-bearing feature on `CGSSetCursorScale` would block that path. Developer-ID distribution tolerates it, but with the stability caveat above.
- **Crash safety**: this is the most concrete finding. A real shipping app (`lacymorrow/juno`, a similarly-shaped "AI agent visibility" tool) tried exactly this — set `mouseDriverCursorSize` while running, restore on exit — and **abandoned it** after users got stuck with a permanently oversized cursor across reboots, because: (a) process crashes left the change on disk with no restore, (b) test/preview code paths weren't guarded and made temporary changes permanent, and (c) even on next launch the app refused to reset it automatically, requiring the user to fix it manually in Settings. They replaced it with a system-blue ring overlay ("already spans every display, is click-through, and cannot outlive the process that draws it") — i.e., they converged on the same locator-ring pattern PocketDesk already has and considers ugly.
- **ScreenCaptureKit reflecting the enlarged cursor**: historically yes — an Apple Developer Forums thread ("Unable to capture only the cursor in macOS Tahoe") describes code that worked through macOS 15 to capture the cursor *at enlarged size*, but **broke specifically in macOS 26 "Tahoe"**: when pointer size is scaled to maximum, `SCStream` now fails to start with "Failed to start stream due to audio/video capture failure." This is an active, apparently-unfixed regression as of the forum post, with no Apple response yet. Given the target OS is macOS 26/27, this is a real landmine for option 1 even if the persistence problem were solved.

**Verdict: feasible in the crudest sense, but not simplest-that-works-well.** No public API, unreliable live-apply, unstable private fallback, App Store blocker, crash-safety is genuinely hard (proven by prior art), and there's a live macOS 26 SCStream regression tied to max pointer size.

## 2. Draw our own pointer on the phone (hide system cursor, send shape+hotspot)

- Set `SCStreamConfiguration.showsCursor = false` (public, documented) to stop compositing the system cursor into frames.
- **Getting the current cursor image**: `NSCursor.currentSystem` (returns an `NSCursor` with `.image` and `.hotSpot`) is the only public accessor, and it is **deprecated as of macOS 15** with no official replacement announced (confirmed on an Apple Developer Forums thread where even an Apple Frameworks engineer only asked "what's your use case?" without giving an alternative). It is deprecated, not removed — still functional today per independent developer testing (codejam.info), but Apple's direction is unclear, so treat it as time-bounded.
- Practical technique used by hobbyist tooling (codejam.info "harvest cursor from any app"): poll `NSCursor.currentSystem` on mouse-moved events (global `NSEvent` monitor, debounced ~200ms) and identify/hash the resulting bitmap; no private CGS calls were needed for this narrower goal.
- Reputable remote-desktop hosts (RustDesk) do send cursor shape+hotspot data cross-platform; their macOS path is Objective-C++ (`platform/macos.mm`) but public search didn't surface the exact private call they use for capture — RustDesk's recent work (PR #16213) is mostly about correctly *rendering* received cursor bitmaps at native size across DPI/platforms (point-size preservation from `NSImage.size` on macOS, alpha-weighted resizing, hotspot realignment), not about macOS capture internals specifically.
- **Latency**: rendering the pointer locally on the phone from a lightweight position+shape message (as PocketDesk's existing `PointerLocation`/probe channel already does) is inherently lower-latency than waiting for the next encoded video frame — this is a genuine, real advantage independent of API risk.
- **Effort**: Medium. You already have 90% of the plumbing (`PointerLocation`, probe/accept protocol, `ViewportTransform`). The new work is: hide system cursor in capture, capture+diff cursor image/hotspot on the host (via `NSCursor.currentSystem`, sent as data once-per-change rather than continuously), and replace the phone's stroked-circle overlay with an actual scaled cursor bitmap.
- **App Store**: fully compatible — everything used here is public API.

## 3. ScreenCaptureKit cursor options in macOS 26/27

- No new cursor-scaling or cursor-metadata API was found for macOS 26 Tahoe beyond the existing `showsCursor` / `showMouseClicks` (click-ripple indicator) booleans on `SCStreamConfiguration`, and `SCStreamFrameInfo` attachment keys (`.status`, `.boundingRect`, `.contentRect`, `.contentScale`, `.dirtyRects`, `.displayTime`) — none of these carry cursor shape/position data.
- The one Tahoe-specific cursor-related finding is negative: the SCStream-fails-to-start regression at max pointer size described above (Apple Developer Forums thread 819931).

## 4. Other options

- **"Shake mouse pointer to locate"**: this is a built-in macOS behavior (Accessibility → Pointer), not something exposed for an app to trigger/toggle programmatically, and it fires from real physical mouse shake input, not synthesized events — not usable here.
- **Phone-side halo/drop-shadow drawn at the known position** using the existing low-latency `PointerLocation` channel, but styled better than the current thick stroked circle (e.g., a soft blurred glow behind a small dot, animated only while `followingMotion` is true, fading out) — same architecture as today, just better visual design. Low effort (S), no new APIs, no permissions, fully App-Store safe.
- **Cropping/zooming the captured cursor region phone-side**: not really applicable since the cursor is a few pixels within a full-frame video stream at reduced resolution (`CapturePixelDimensions.fitted`) — cropping would need to know cursor position anyway (same data you'd need for option 2/4b) and re-encoding a magnified crop client-side of compressed video is visually poor (blurry) compared to compositing a crisp vector/bitmap pointer.

## Recommendation

- **Quick win to ship now (S effort)**: Keep `showsCursor = true` as-is (don't fight the video-composited cursor), and replace only the *look* of the existing locator-ring overlay in `PointerLocatorOverlay` — e.g., a soft glow/halo (blurred, low-opacity, animated) instead of a hard 5pt black+white stroked circle — reusing all existing plumbing (`PointerLocator`, `PointerProbeState`, the probe/accept protocol). Zero new permissions, zero new APIs, zero App Store risk, ships today.
- **Best long-term approach (M effort)**: Move to option 2 — `showsCursor = false` + host sends actual cursor bitmap/hotspot (via `NSCursor.currentSystem`, monitored) + phone renders a crisp, scaled-up native pointer using the same low-latency position channel already built. This gives the best visual quality (looks like a real, big cursor, not a marker) and the best latency (local render, no video round-trip) with no App Store risk. The only caveat is `NSCursor.currentSystem`'s deprecation with no announced replacement — worth an Apple Feedback/Radar to hedge, but it is safe to build on today.
- **Explicitly avoid**: system-wide pointer-size scaling (`mouseDriverCursorSize` / `CGSSetCursorScale`). It has no public API, does not reliably apply live via `defaults write`, requires an unstable private call to force-apply, cannot be safely guaranteed to restore after a crash (proven failure mode in a comparable shipped app, juno), is an App Store rejection risk, and currently trips a macOS 26 SCStream-start regression at maximum pointer size.
